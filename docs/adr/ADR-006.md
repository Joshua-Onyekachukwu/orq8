# ADR-006 — App-Level Authorization First, RLS as Phase 16 Hardening

**Status:** Accepted · **Date:** 2026-08 · **Scope:** Security/authorization

## Context
Multi-tenant data must be isolated. Postgres RLS is powerful but adds complexity (per-org policies, Drizzle integration, testing overhead) at a phase where the platform is small.

## Decision
Enforce tenant isolation + authorization in a deterministic **AuthzService** at the API layer from Phase 1 (`org_id` on every row; org derived from session, never client). Add **Postgres RLS** in Phase 16 as defense-in-depth.

## Consequences
- Faster iteration on the permission model while the platform is small; every denial is audited.
- RLS hardening is additive, not a rewrite; isolation tests (44) guard both layers.
- Risk accepted: a bug in the app layer could leak data pre-RLS — mitigated by isolation tests from day one.
