# ADR-003 — pg-boss First, Temporal Later

**Status:** Accepted · **Date:** 2026-08 · **Scope:** Durable workflows

## Context
Long-running organizational workflows must survive process/model/tool failure (§72). Temporal is a strong candidate but adds infrastructure; the brief itself warns against over-engineering before workload requires it.

## Decision
Define a **WorkflowRuntime interface**; ship adapter 1 = **pg-boss** (Postgres-backed, free, durable); adapter 2 = **Temporal** (free self-host or cloud) later, implementing the same interface. Domain code depends only on the interface.

## Consequences
- Zero extra infrastructure at Phase 1; workflows are durable in Postgres today.
- Swap to Temporal is a config/adapter change — no domain-code rewrite.
- pg-boss limitations (no built-in workflow DAG) are handled by our declarative WorkflowSpec + step state (15).
