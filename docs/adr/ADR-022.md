# ADR-022 — Supabase Is the Platform Backend

**Status:** Accepted · **Date:** 2026-08 · **Scope:** Infrastructure / platform

## Context

All production infrastructure for ORQ8 runs on **Supabase** (managed Postgres 16 + pgvector on the free tier, deployed alongside Vercel and GitHub). Future work — including the pricing, billing, and Work Credits architecture (Build Spec §3 / docs/60) — must assume Supabase as the backend. This ADR consolidates the existing decisions into a single pointer so build agents never plan around a different stack.

## Decision

1. **Database:** Supabase Postgres 16 + pgvector. All schema via Drizzle migrations in `packages/db` (ADR-002), applied by the `DB Migrate` GitHub Action on push to `main` — never Supabase dashboard SQL.
2. **Auth:** app-level session auth with httpOnly cookies (ADR-007). Supabase JWKS URL may be used to verify tokens, but Supabase Auth is not the primary identity path.
3. **Access pattern:** the web never talks to Supabase directly. All DB access goes through the API (`apps/api`, Fastify, ADR-001), which enforces tenant scoping and session verification (docs/58).
4. **Authorization:** app-level authorization layer first; Supabase RLS deferred as Phase 16 hardening (ADR-006).
5. **Storage:** Supabase Storage (S3-compatible) for v1 documents/uploads — supersedes the MinIO-first option in ADR-005 now that Supabase is the host; revisit R2/S3 only if we leave the platform.
6. **Realtime:** SSE before WebSockets (ADR-008) for the agent activity feed; Supabase Realtime not required.
7. **Billing:** Supabase has no billing product. Payment processing (Stripe or similar) and the pricing/billing tables (entitlements, metering, `credit_balances`, `pricing_versions`) remain external services + Supabase tables respectively.

## Consequences

- Local dev uses the dockerized Postgres in `infra/docker-compose.yml`; production uses Supabase. The same Drizzle schema serves both.
- The pricing/Work Credits implementation (docs/60) stores all entitlement, metering, and billing records in Supabase tables via Drizzle; only payment execution is external.
- Cost notes: Supabase free tier (500 MB DB) covers Phase 1–3 (1–5 agents); move to Pro when metering volume or storage demands it.
